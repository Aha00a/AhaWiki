# 위키 텍스트 기반 Kanban 기능 설계안

사용자 의도: **위키 문법(불릿 기반)을 원본 데이터로 사용**하고, 화면은 **Kanban 보드 UI**로 렌더링하며, 드래그 앤 드롭 결과를 다시 **위키 텍스트로 저장**합니다.

---

## 1) 결론 (좋은 방향인가?)
네, 아주 좋은 방향입니다.

- 기존 위키 편집 경험을 유지합니다.
- 구조화된 데이터베이스 없이도 Kanban을 도입할 수 있습니다.
- "텍스트가 진실의 원천(source of truth)"이므로 백업/이력/비교가 쉽습니다.
- UI는 시각적으로 편하고, 저장은 단순 텍스트라 구현 리스크가 낮습니다.

핵심은 **문법 제약을 명확히 정의**하고, **파서-렌더러-역직렬화(serializer)**를 안정적으로 만드는 것입니다.

---

## 2) 제안 문법 (사용자 예시 기준)
예시:

```wiki
== 할일
 * 집에가기
 * 설거지
== 하고있는일
 * 청소
  * 환기중
== 완료
 * 쓰레기 버리기
```

해석 규칙:
- `== 섹션명` → Kanban **리스트(Column)**
- 섹션 아래 1레벨 불릿(`* ...`) → **카드(Card)**
- 카드 아래 하위 불릿(`  * ...`) → 카드의 **댓글(Comment)**

제약(권장):
- Kanban 블록 안에서는 제목 레벨을 `==`로 고정.
- 카드는 반드시 1레벨 불릿만 허용.
- 댓글은 카드 바로 아래 2레벨 불릿만 허용.
- 3레벨 이상 불릿은 무시하거나 일반 본문으로 보존(정책 선택).

---

## 3) 내부 데이터 모델 (메모리)
렌더링/드래그 처리용 중간 모델:

- Board
  - columns: Column[]
- Column
  - id: string (안정 ID)
  - title: string
  - cards: Card[]
- Card
  - id: string (안정 ID)
  - text: string
  - comments: Comment[]
- Comment
  - text: string

ID 전략(중요):
- 초기 파싱 시 카드별 ID가 없으므로 `해시(섹션명+텍스트+순번)`로 임시 생성.
- 더 안정적으로 하려면 숨김 토큰을 카드 텍스트 끝에 부여:
  - 예: `* 집에가기 <!--kanban:card:abc123-->`
- UI 이동 후 저장 시 이 ID를 유지하면 충돌/정렬 오류가 줄어듭니다.

---

## 4) 렌더링 규칙
1. 문서에서 Kanban 대상 블록을 파싱.
2. 컬럼/카드/댓글 모델 생성.
3. 보드 컴포넌트로 렌더링.
4. 카드 drag & drop 지원:
   - 같은 컬럼 내 순서 변경
   - 다른 컬럼으로 이동

UI 동작 권장:
- 카드 클릭 시 원문 텍스트(카드+댓글) 빠른 편집.
- 저장 전 "위키 텍스트 미리보기" 제공.
- 충돌 시(동시 편집) 머지 안내.

---

## 5) 저장(역직렬화) 규칙
드래그 결과 모델 → 위키 텍스트로 재생성:

- 컬럼 순서대로 `== 컬럼명` 출력
- 카드 순서대로 ` * 카드텍스트` 출력
- 댓글 순서대로 `  * 댓글` 출력

저장 시 주의점:
- Kanban 블록 외부 텍스트는 절대 훼손하지 않기.
- 줄바꿈/공백 스타일을 최대한 원문과 동일하게 유지.
- 실패 시 원문 롤백 가능해야 함.

---

## 6) 파서 구현 전략
안전한 방식은 "전체 위키 파서"보다 "Kanban 블록 제한 파서"입니다.

권장 절차:
1. 문서에서 Kanban 블록 범위 탐지.
2. 해당 범위만 라인 단위로 파싱.
3. 규칙 위반 라인은 `raw`로 보관.
4. 저장 시 `raw` 라인은 보존 또는 하단으로 재배치.

이 방식이 좋은 이유:
- 기존 위키 문법 전체를 깨지 않음.
- 기능 범위를 작게 잡아 버그를 줄임.

---

## 7) MVP 범위 제안
1차(MVP)
- 컬럼/카드 렌더링
- 카드 이동(컬럼 간/내)
- 위키 텍스트 저장

2차
- 카드 댓글 편집
- 새 카드/컬럼 추가
- 삭제/복구

3차
- 실시간 동시편집 충돌 처리
- 권한/감사 로그 강화

---

## 8) 사용자 예시의 저장 결과
사용자가 준 입력을 그대로 보드로 렌더링 가능하며,
예를 들어 `청소` 카드를 `완료`로 드래그하면 저장 텍스트는 아래처럼 바뀝니다:

```wiki
== 할일
 * 집에가기
 * 설거지
== 하고있는일
== 완료
 * 쓰레기 버리기
 * 청소
  * 환기중
```

즉, **UI는 Kanban**, **저장은 위키 텍스트**라는 목표에 정확히 맞는 설계입니다.
